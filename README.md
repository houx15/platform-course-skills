# 平台课程生产工具包

这套 Skills 帮助内部教师与 Codex、Claude 等 Agent，把 Word、Markdown、PDF、视频、HTML、图片及零散教学材料，逐步整理成可预览、可批注、可检查并可提交到 Mind Imprint 学生端的 CourseDefinition 2.0 课程。

教师只使用一个主入口：`build-platform-course`。材料分析、课程结构补全、媒体检查、真实渲染预览、批注修改、独立终审和发布都由主入口按当前阶段调用，不要求教师理解 JSON、validator 或内部 Skill 分工。

## Agent 接手协议

如果你是正在读取本 README 的 Agent，不要只向老师复述本文。你应先判断 Skills 是否已安装，再判断老师当前需要的是以下哪一种工作：

1. **只安装或更新**：根据当前宿主选择 Codex 或 Claude，自行完成安装或更新，确认 9 个课程 Skills 与 `_course-toolkit` 均可用，然后请老师开启一个新任务以载入最新版 Skills。此时不要擅自开始制作课程。
2. **开始一门新课程**：使用唯一教师入口 `build-platform-course`，按“理解材料 → 确认教学设计与逐页计划 → 制作并自检 → 预览并发布”推进。
3. **继续已有课程**：读取当前 `.course-work` 和可用课程文件，告诉老师上次停留阶段、未解决问题和下一步；已经确认逐页计划或进入 Blueprint、编译、预览、审查、发布阶段的课程不补做新教学设计和学生视角预审。不要从头重新生成，也不要因为课程早于新检查流程就要求返工。

课程目录中存在 `.course-work/session.json` 时默认按继续处理。`.course-work` 必须放在当前课程内容所在的独立文件夹下面；如果新课程目前只是一个新文件，先为它创建新的课程文件夹，再在该文件夹内初始化 `.course-work`。除非老师在理解现有进度将被分离后明确要求新建，否则不得覆盖既有课程身份或进度。

如果信息不足，只向老师询问以下必要内容：

- 课程文件夹的绝对路径；
- 新建还是继续；
- `index.md` 或主要入口材料的绝对路径。没有 `index.md` 时，可以接受若干主要文件路径。

不要要求老师选择内部 Skill、阅读或编辑 JSON、运行命令、启动预览服务，或者提前把材料整理成标准格式。这些工作由 Agent 自己执行。与老师的沟通使用中文；稳定 ID、文件路径、Contract 字段和必要排错信息可以保留原文。

接手课程后，Agent 必须：

- 先介绍四阶段流程；完整盘点材料，先完成以核心方法论为主线的教学设计，再生成逐页计划，并在交给老师前完成一次学生视角教学审查；请老师一次确认完整设计和计划后，连续工作到首次完整预览；
- 根据课程名称从 33 门正式课程目录中提出最可能的课程，但不得替老师自动确认。老师确认课程名称后，固定 slug、封面 OSS key、分类、短介绍、完整介绍和工具卡全部由目录自动带入，老师不填写或审核这些内部字段；
- 自动盘点材料，并从现有文件识别视频、独立 HTML 和完整 PDF；只有用途确实无法判断时才集中提问；
- 教学设计明确核心问题、核心方法及步骤、案例练习、学习路径、累计学习成果和迁移任务；逐页计划再明确每页对应的教学阶段、方法步骤、理解变化、素材、学生行动、参考关系和大致 layout，并说明全部素材的使用或排除去向；
- 交给老师前，从学生视角检查是否先教后练、是否有示范和支架、是否像连续考试、是否有累计进展和迁移；发现问题先自行修改；
- 教学设计和逐页计划确认后，自行生成课程首尾、完整 Part/Slice、layout、Blocks、narrations、workflow、导航和完成规则；
- 自行编译、验证，用真实 renderer 逐页截图做一次初步视觉检查；明显排版或内容错配先修好，再把预览交给老师；
- 读取预览批注，将机械修改、教学语义修改和学生端运行问题分开处理；明确批注直接执行，只有歧义、冲突或超出批注范围时才追问；
- 每次修改后重新编译、检查和预览；老师标记已解决的批注保持已解决，不得被新检查自动重开；
- 预览结束且没有待处理批注时，主动问老师是否发布。尚未绑定课程目录时先只问课程名称；没有对当前发布的明确批准，不得上传或发布。

不要在课程开始时索取 `OSS_ADMIN_KEY`。只有老师确认要发布且确实缺少凭证时，才向老师索取；由 Agent 写入被 Git 忽略的本地 `.env`，不得回显或提交到 Git。构建、检查、预览和批注都不构成发布授权。

老师可以把下面这句话连同课程路径一起发给自己的 Agent：

```text
请阅读这个仓库的 README.md。不要只总结说明，请按照“Agent 接手协议”判断我是在安装、开始新课程还是继续已有课程，并主动带我完成下一步。所有教师沟通使用中文；未经我对具体发布计划明确批准，不要上传或发布。
```

## 33 门课程绑定与封面协议

以下协议供接手课程的 Agent 执行。不要把内部命令交给老师。

老师在这个环节只做一个选择：

- 选择或确认课程名称。

固定 slug、封面、分类、短介绍、Cards 和 Introduction 是平台预先定稿的课程配置。Agent 不要求老师分别审核、确认或改写，也不能把它们变成额外选择。

### 先提议课程，再由老师确认

代码提议课程名称，老师只确认课程名称。读取课程正式名称和别名后，调用 `manage-course-catalog.py propose`。匹配顺序为完全一致、标准化一致、模糊相似度排序。

向老师展示最可能的正常课程名称，例如：

```text
我判断这最可能是《把争议放回证据里：立场光谱与视角对照矩阵》。请确认；也可以先完成课程预览，提交前再确认。
```

不得把模糊匹配第一名静默写成最终选择。不要让老师选择 `catalogId` 或 slug、挑选封面、填写分类、抄写 Cards 或编辑介绍 JSON。老师确认课程名称后，调用 `manage-course-catalog.py confirm` 保存绑定。

老师应在课程身份确定后尽早确认名称；任何 `save-preview` 或 `publish` 之前都必须存在当前有效的确认记录。旧版本制作的课程也不能跳过。正式目录、别名或对应字段变化后，要求老师重新确认。

确认后，从固定目录原样取得 `slug`、`blurb`、`category`、`cardIds`、完整 `introduction` 和封面记录。封面记录固定包含 `cover/course-cover.webp`、完整 OSS key、WebP 哈希和大小。所有值都是平台定稿，不要求老师分别审核、确认或改写。不要让 AI 根据课程材料重新猜测或改写这些字段。完整介绍固定包含 `hook`、`whatYouDo`、`takeaways`、`alignment` 和 `keywords`。不要提交 `featured_rank` 或 `featuredRank`。

### 把目录字段提交到正确接口

Cards 不属于 `CourseDefinition`。Cards 不通过 `ship` 提交。将目录字段与课程定义一起发送到 `PUT /api/v1/admin/courses/{slug}/definition`：

请求结构为：

```json
{
  "definition": { "...": "CourseDefinition 2.0" },
  "blurb": "课程短介绍",
  "cardIds": ["belief-spectrum", "perspective-matrix"],
  "category": "stance-value",
  "introduction": {
    "hook": "...",
    "whatYouDo": "...",
    "takeaways": ["..."],
    "alignment": {
      "ib": ["..."],
      "otherIntl": ["..."],
      "domestic": ["..."]
    },
    "keywords": ["..."]
  }
}
```

这里的 `cardIds`、`category` 和 `introduction` 必须全部来自同一条已确认目录记录。学生端查询结果可能把 Cards 返回为 `card_ids`；教师工具提交时仍使用 `cardIds`。

### 33 张固定封面由管理员一次性预置

教师工作流不生成封面，不调用图片生成工具，不要求老师选择或确认封面，也不把封面复制进课程工程。33 张定稿 WebP 由平台管理员一次性上传到代码固定的 OSS key：`courses/course-01/cover/course-cover.webp` 至 `courses/course-33/cover/course-cover.webp`。

老师反复保存或发布时，封面不进入教师素材上传清单。发布工具只向 ship 发送 `coverAssetPath: "cover/course-cover.webp"`，学生端根据固定 slug 推导完整 key；随后工具下载短期 `coverUrl` 并核对其字节哈希与目录记录一致。封面从同一条固定目录记录自动取得，不生成封面，不要求老师确认封面。

## 老师如何使用

老师只需要准备材料、回答教学判断、查看预览并批准最终提交。课程目录、JSON、格式检查、预览服务和发布操作由 Agent 处理。

老师不需要选择或理解客户端的内部工作模式。正常情况下，Agent 先盘点材料，形成“核心方法论如何通过案例被讲解、示范、练习和迁移”的教学设计，再生成逐页计划。Agent 会先代表学生走查这一流程并自行修订，然后把教学设计和逐页计划一起交给老师确认一次。确认后，Agent 持续处理到课程可以预览。只有缺少必要文件、材料互相冲突、正确答案无法确定等真正阻塞项才会额外询问。

老师只需要用中文自然交流，不需要把批注或确认翻译成英文。Agent 应使用中文说明材料判断、设计方案、检查结果和发布风险；只有稳定 ID、文件路径、Contract 字段或排错命令等必要技术内容保留原文。

如果课程名称与正式的 33 门课程目录相近，Agent 会直接说“我判断最可能是《……》，请确认”。这只是推荐，不能静默选中。老师可以一开始确认，也可以回答“先做预览，提交前再定”。即使课程是用旧版工具做的，最终提交前也必须选定一门；随后 `category`、学生端结构化课程介绍和对应工具卡会自动取得。老师不审核这些固定内容，也不需要编辑 JSON。

### 第一步：准备课程文件夹

为每门课准备一个独立文件夹，把现有材料原样放进去。一个人可以同时处理多门课，但 `.course-work` 必须位于对应课程内容的文件夹下面；如果新课程目前只是一个新文件，Agent 必须先创建新的课程文件夹。Word、Markdown、文本、PDF、PPT、图片、MP4、字幕和独立 HTML 都可以混合存在，不需要提前整理成统一格式。

建议增加一个 `index.md`，简单写清楚：

- 这门课大概讲什么；
- 各份材料是什么、希望怎样使用；
- 已知的学生对象、时长或教学目标；
- 哪些原文、图片、视频或互动必须保留；
- 暂时拿不准的问题。

这份说明不需要完整。Skill 会继续盘点材料，只在遇到真正阻塞项时询问。不要只提供 ZIP；ZIP 不参与课程分析。完整 PDF、视频和 HTML 应保留为独立文件。

示例目录：

```text
my-course/
├── index.md
├── lesson-notes.docx
├── reference-report.pdf
├── demonstration.mp4
├── interaction.html
└── images/
```

### 第二步：安装或更新 Skills

在 Codex 中发送：

```text
帮我安装这套 Skills：https://github.com/houx15/platform-course-skills
```

如果已经安装过、现在需要更新，发送：

```text
请把这套课程 Skills 更新到最新版本：https://github.com/houx15/platform-course-skills
```

安装或更新完成后，开启一个新任务，使 Codex 载入最新版 Skills。

### 第三步：开始一门新课程

在课程文件夹中打开 Codex，或者在消息中提供课程文件夹和入口材料的绝对路径。然后发送：

```text
使用 $build-platform-course，把下面的已有材料整理成一门完整、可预览的平台课程。

课程文件夹：
<课程文件夹的绝对路径>

入口材料：
<index.md 或主要材料的绝对路径>

请先完整盘点材料，先做一份以核心方法论为主线的教学设计，再从它生成逐页计划。教学设计要说明核心问题、方法步骤、案例练习、讲解与示范、支架、累计学习成果和迁移任务；逐页计划要把每个 Slice 当成一张教学幻灯片，说明这一页在课程中的位置、承接什么、当前重点、为下一页准备什么、学生看到什么和做什么、素材与大致排版。课程开始必须有有效导入，让学生理解今天要解决什么、为什么值得学以及接下来会怎样推进；可以使用故事、案例冲突、观察任务、演示、问题情境或课程总览，不要直接扔出一道题。未使用清单重点展示图片、HTML 和视频是否都被覆盖。交给我之前，请先从学生视角完整审查一次，避免把课程做成连续答题。我一次确认整体设计和计划后，请自动完成 layout、workflow、格式检查、逐页视觉自检和首次预览。除非遇到无法从材料判断的真正阻塞项，不要反复让我确认。未经我明确批准，不要上传或提交课程。
```

如果没有 `index.md`，列出主要文件即可。不要让 Agent 猜测课程文件夹；路径必须明确。

### 第四步：确认教学设计与逐页计划

Agent 先完成教学设计，再生成逐页计划。教学设计说明核心问题、学生起点与终点、核心方法及步骤、案例、学习路径、累计学习成果和迁移任务。逐页计划一行对应一个 Slice，至少说明对应教学阶段和角色、方法步骤、理解变化、使用素材、学生看到什么、学生做什么、参考材料与题目的对应关系、大致 layout，以及“承接上一页—本页重点—为下一页准备什么”。计划中的“未使用或仅用于备课”重点只展示图片、HTML 和视频，方便老师快速确认这些关键媒体是否都被覆盖；PDF、文档、表格和文字材料仍保留在完整材料盘点中。

每个 Slice 都按一张教学幻灯片来判断：一页只保留一个主要教学重点或行动，画面要有明确焦点，内容密度适合一屏，页与页之间有可感知的推进。每一页都要呈现两层上下文：它承接了上一页的哪个观察、结论或学习成果，以及它位于整套方法或学习路径的哪一步。学生还要知道为什么现在看这份材料或做这个练习、应该使用什么方法或证据，以及完成后会推进到哪里。可以使用标题、短引导、讲解、方法步骤轨道、“刚才／现在／接下来”或持续更新的成果状态，不要求每页都塞一个大 `richText`。内部的步骤 ID 或计划字段不算呈现，必须真正写进学生看到的内容中。

在老师看到它们以前，Agent 会先以学生视角完整走一遍，检查学生是否知道为什么学、方法是否先讲解和示范、练习是否有支架、页面是否像连续考试、是否持续形成一份学习成果、最后能否迁移。随后逐页检查每个 Slice 是否有足够的当前上下文、是否说清它在整体方法中的位置和本页目的；再按顺序检查每一对相邻页面，确认前一页的观察、结论、方法步骤或学习成果真实成为后一页的起点。素材覆盖检查回答“材料有没有被用到”，这项语义检查回答“这些页面有没有组成一门连贯的课”。发现问题会先修改设计和计划，不把内部返工交给老师。

老师一次确认完整教学设计和逐页计划，或指出需要调整的阶段和页面。老师不审核 JSON、稳定 ID、workflow 细节或 validator。

确认后，Agent 自动完成详细结构、编译、检查和视觉自检。只有以下真正阻塞项会暂停：

- 必要材料缺失或损坏；
- 多份材料表达互相冲突的教学目的；
- 正确答案、评分依据或必做完成规则无法确定；
- 必须在多个原始 PDF、视频或 HTML 中选择，但现有说明不足以判断。

这些情况会合并成尽可能少的问题。其余事项由 Agent 先做初稿并在真实预览里一起判断。老师确认教学设计和计划时主要检查：

1. **材料怎么使用**：哪些给学生看，哪些只是教师参考；是否需要完整 PDF；是否有长视频或独立 HTML 互动。
2. **真正教什么方法**：核心方法是否清楚，学生是否先理解和看到示范，再带入案例练习。
3. **学生怎样发生变化**：学生起点、学习路径、累计成果和最终迁移是否连贯，是否存在大量重复答题。
4. **每页怎样服务教学**：Part/Slice 顺序、每一屏对应的方法步骤、学生看到什么、做什么、怎样完成。
5. **复杂互动是否正确**：视频何时暂停、弹出什么问题；HTML 完成时提交什么学习数据；答案、反馈和必做规则是否符合教学意图。

整体设计和计划确认后，老师不再逐项审批课程首尾文案、layout 或 workflow。Agent 完成制作并逐页截图自检后，老师在真实 renderer 预览中重点检查：

- 顺序是否符合自己的教学思路；
- 每屏内容是否过多；
- 图片、PDF、视频、HTML 或题目是否用在合适的位置；
- 学生行动与完成条件是否明确；
- AI 补充的解释、答案、反馈和总结是否准确。

可以直接用自然语言修改，例如：

```text
第二部分的概念解释太早了。先让学生观察视频，再总结规律。

这一页不要放完整 PDF，只展示两张关键图片；PDF 放到下一页供学生查证。

这道题不应该答错一次就通过，第二次错误后再显示提示。
```

老师在预览批注中提出的明确修改已经是修改指令，Agent 不会再要求批准同一句话。只有批注含义不清、互相冲突，或实际解决方案会明显超出批注范围时才会追问。

### 第五步：Agent 制作并自检

Agent 会检查课程结构、每页 layout 和 workflow，以及 PDF、视频、字幕、HTML、互动协议和所有素材路径。

静态检查通过后，Agent 会先用真实学生端 renderer 打开检查模式。这个模式允许直接跳到每个 Slice，不需要先答题或完成视频/HTML。Agent 保存并实际查看每页截图，像审一组教学幻灯片一样检查：单页内容密度与画面焦点是否合适，是否能看出与上一页的联系和整体框架中的位置，当前教学目的是否清楚，以及学生是否能理解为什么现在要做这件事；同时检查明显拥挤、空分栏、文字或媒体太小、图片和题目错配、题目引用的资料不在当前页、控件被裁切以及运行错误。发现明显问题时先修改并重新检查，再把链接交给老师；不要求老师观看这个内部修复过程。

- **必须修复的问题**会阻止预览或提交；
- **非阻塞提醒**会记录并随预览一起说明，不会停下来要求老师逐项接受；
- **页面内容较密等普通建议**会展示，但不会阻止生成预览。

老师不需要修改 JSON 或执行检查命令。提供缺失材料、回答教学问题，或者允许 Agent 对已经说明的机械问题进行修复即可。视频格式不兼容或文件很大时，Agent 会说明问题并提出可选的 `ffmpeg` 处理方案；老师确认具体方案后，Agent 可以在当前任务中保留原件并生成候选视频。候选视频只有在老师实际播放并确认后，才会进入课程。

### 第六步：在浏览器中预览和批注

检查通过后，Agent 会打开本机预览链接。这里使用固定在 `course-authoring-v1.6.0` 的真实学生端 renderer；它包含 PDF 放大阅读、加载反馈与报告滚动能力，修复 PDF 外部打开占用课程标签页、空分栏和隐藏 Block 占位等问题，并支持用于结构化静态讲解的 `richText`。开场、结尾和逐页讲解在本地预览中可以静音。`127.0.0.1` 是本地地址，这个链接只能在老师当前这台电脑上观看。老师完成本地预览或终审后，Agent 必须主动提醒：需要同事或其他老师预览时，下一步是在明确批准后发布到学生端并分享学生端页面；不要发送 ZIP 包、课程文件夹或本地链接。

Agent 默认把检查模式交给老师，所以页面顶部始终有独立的“上一页 / 下一页”，即使题目、视频或 HTML 尚未完成也能直接翻到其他 Slice；这只服务于本地审阅，不会修改学生端完成规则。只有老师明确要求体验学生的完整 Workflow 时，Agent 才另开普通预览。批注栏仍可打开使用。

右侧“课程批注”是额外的教师预览工具，不属于学生端课程界面。当前版本收起时占 46px、展开时占 330px；学生端本身还有自己的侧边栏，因此判断课程真实排版时应先收起教师批注栏，需要留言时再展开。这个本地页面验证共享课程 renderer，不能单独证明学生端完整外壳与侧边栏组合后的最终比例；涉及外壳的显示问题应记录为预览或学生端运行问题，不得通过修改课程 JSON 掩盖。

老师需要：

1. 从课程开场开始；
2. 访问每一个 Slice；
3. 实际操作相关视频弹题、HTML、PDF、答题和翻页；
4. 检查全屏和左右分栏是否清楚；旧课程若使用上下分栏，也要确认没有形成难读的横向薄条；
5. 正常操作课程时保持“批注模式”关闭；需要留言时打开批注模式，直接点击页面中的组件选中对应的 Block 或图片，也可以选择整页 Slice；此时点击不会触发学生交互；
6. 写下具体意见。已有批注可以修改、删除、标记已完成或重新打开；只有在当前预览确实解决问题后才标记完成；
7. 看完后点击“确认我已完整审查”。批注仍可保持待处理、标记完成、删除或重新打开；老师标记已完成的批注不会被系统擅自改回未解决。走到课程最后且没有待处理批注时，完成页会显示“下一步：发布到学生端”，用于把确认结果交回 Agent；它不会绕过正式发布前的计划和确认。

一条有用的批注应同时说明问题和期望，例如：

```text
这一页右侧图片太小，无法比较两种结构。希望把图片放到单独一页并放大，文字总结移到下一页。

视频在 01:24 出题太早，学生还没有看到完整操作。请把问题移到操作结束后。

完成 HTML 活动后页面没有继续，像是运行错误，不是课程文案问题。
```

保存批注后，在 Codex 中发送：

```text
请处理我刚才在预览中留下的全部批注。先告诉我哪些可以直接修改，哪些会改变教学含义，哪些属于学生端运行问题。
```

Agent 会把文案修正、语义修改和 renderer bug 分开处理。批注已经明确说明目标时直接修改；只有解决方案存在歧义、冲突或明显超出批注范围时才再次询问。修改后必须重新生成、重新检查并打开新预览；旧预览不能证明新版本已经通过。

### 第七步：决定继续修改还是发布

老师可以继续留下批注，也可以把已经解决的批注标记完成、删除误写批注或重新打开。Agent 处理修改后会重新编译、检查、逐页自检并给出新预览。

当老师完成预览且当前没有待处理批注时，Agent 主动询问：`现在发布到学生端吗？` 这只是进入发布流程，不代表已经上传。如果还没有选择 33 门课程中的对应课程，Agent 先让老师只选择课程名称；分类、Cards、Introduction、封面和固定 slug 由代码自动匹配。

### 第八步：保存到学生端或正式发布

老师确认要发布后，仍然只调用主入口：

```text
请发布当前课程到学生端。如果还没有绑定正式课程，请先让我选择课程名称；然后告诉我将创建还是更新、需要上传和复用的素材数量以及风险。在我明确批准以前不要执行。
```

老师可以选择：

- `save-preview`：保存到学生端预览状态，适合第一次联调；
- `publish`：正式发布，并触发学生端 ship/TTS。

Agent 会先展示精确 dry run。确认课程 ID、创建或更新、素材数量和风险后，老师再明确批准，例如：

```text
我批准刚才这份发布计划。批准理由：课程已经完成预览和终审，可以保存到学生端预览状态。
```

任何课程内容、素材、远端状态或发布选项变化都会使旧批准失效。老师在发布时才选择课程名称也不需要重做已经完成的预览：发布器只在提交数据中套用目录固定的课程 ID 和标题，不改写本地已审课程。修改同一门课时始终使用相同课程 ID；未改变的素材会根据相同课程 ID、相对路径和文件哈希复用。

封面不属于教师素材上传。33 张定稿 WebP 由管理员一次性预置在固定 OSS key；学生端 authoring API v1.4.0 使用课程相对路径 `coverAssetPath: "cover/course-cover.webp"` 绑定，工具自动核对 `coverUrl` 返回字节与固定目录哈希一致。老师重复保存或发布不会重新上传封面。

第一次需要真实提交时，老师可以把管理员提供的 `OSS_ADMIN_KEY` 交给 Agent。Agent 会把它写入课程目录的本地 `.env`，同时确认 `/.env` 已加入 `.gitignore`；老师不需要执行命令，也不需要设置系统环境变量。Git 中只保留值为空的 `.env.example`。进程环境变量优先于 `.env`，方便部署环境覆盖本地设置。

Agent 不得回显凭证，也不得把它写入命令参数、课程材料、`.course-work`、日志或 Git。其他老师使用自己的 Key 时遵循完全相同的方式；每台电脑和每个课程仓库分别保管本地 `.env`。

### 继续上一次工作

课程进度保存在课程文件夹的 `.course-work/` 中。重新打开课程后发送：

```text
使用 $build-platform-course，继续处理这门课程：
<课程文件夹的绝对路径>

请先恢复已有进度，告诉我上次停在哪一步、有哪些未解决问题和下一项需要我决定的事情。不要重新开始，也不要上传。
```

不要删除 `.course-work/` 来“重新生成”。新增加的逐页计划、语义检查和 Agent 视觉检查只在以后制作或修改课程走到相应阶段时执行；它们不会因为历史记录里缺少这些文件，就把已经处理完成的旧课程退回重做。课程格式和学生端接口没有变化。材料、设计或素材真的发生变化时，Skill 才重做受影响的工作。

### 老师不需要做的事情

- 不需要阅读或手工修改 `course.json`；
- 不需要选择内部子 Skill；
- 不需要自己运行 validator、预览服务器或上传脚本；
- 不需要在学生端创建教师账号；
- 不需要在每次修改后重新创建课程；
- 不要用“页面能打开”代替完整的逐页和互动检查。

## 教师生产流程

新课程使用四个教师可见阶段；`.course-work` 保存可恢复的工作记录，但老师不需要理解 gate：

1. 安全确认课程目录、身份与输入材料。
2. 盘点材料，自动区分学生内容、教师设计、参考材料、完整 PDF、视频和独立 HTML；只上报真正阻塞项。
3. 根据材料形成受众、前置知识、课程目的、学习目标、时长和评价意图，并给每份材料一个明确去向。
4. 先生成以核心方法论为主线的教学设计，明确学生起点与终点、方法步骤、核心案例、讲解/示范/练习顺序、累计学习成果和迁移任务。
5. 从教学设计派生逐页计划；一行对应一个 Slice，说明教学阶段、教学角色、方法步骤、学生理解变化、素材、行动和大致 layout。
6. AI 在交给老师前代表学生完整走查，检查先教后练、示范与支架、答题负担、累计进展、动机节奏和迁移；同时逐页检查当前上下文与整体位置，并检查每一对相邻页面的承接关系；先自行修订，再让老师一次确认完整教学设计和逐页计划。
7. 确认后，AI 补齐每个 Slice 的明确 layout、Blocks、narrations、workflow、导航和完成规则。
8. 从 `.course-work/course-blueprint.json` 确定性编译 `course/course.json`，不得直接修改生成文件。
9. 使用学生端共享 Zod contract 和专项检查器验证 CourseDefinition 2.0、PDF、MP4、字幕、视频交互和 HTML 协议。
10. AI 先用真实学生端 renderer 的检查模式直接打开每个 Slice、截图并查看，修掉明显排版和内容错配后再给老师预览。
11. 教师可以在检查模式中跳过未作答内容，逐页查看并在侧栏写结构化批注。`apply-preview-feedback` 处理批注后重新编译、校验、AI 自检和预览。
12. 没有待处理批注时，AI 主动询问是否发布。教师确认后按原有发布逻辑上传必要 OSS 素材，保存或更新同一稳定 slug 的课程，并按要求 ship。

课程会绑定到正式的 33 门课程目录。老师只确认课程名称；绑定记录固定决定 slug、封面 OSS key、短介绍、七类分类、结构化介绍和工具卡，旧课程也不能跳过。封面不进入教师确认或教师素材上传流程。

任何真实输入、Blueprint、素材或批注变化都会让受影响的后续结果重新生成。`teachingDesign`、学生视角预审和 Slice 语义连贯性审查只要求新课程或仍在重新设计的课程采用；旧课程不会仅因缺少后来新增的工作记录而失效，也不会被要求重新完成已经确认的教学问题。课程格式、学生端接口和发布逻辑没有因此改变。

## CourseDefinition 2.0 与学生体验

课程打开后先展示可根据学生历史实时生成的开场；静态 fallback 说明学什么、预计用时，并提供“开始学习”。正文由 Part 和一屏一个的 Slice 组成。每个 Slice 使用学生端支持的预定义 layout；新课程优先使用全屏、左右分栏或网格，不默认生成容易形成横向薄条的上下分栏。页面中的素材、讲解、等待、交互和翻页由显式 workflow 驱动。

支持的 Block 包括短文本、结构化静态 `richText`、图片组、PDF、视频、交互 HTML、填空和单选。短段落继续用 `text`；课程总览、当前方法位置、重要概念、方法步骤、带标注的示范、对照关系、证据阶梯、定义组、表格、量规和总结卡等需要清晰信息层级的静态讲解优先使用 `richText`。`richText` 还可以用克制的 HTML/CSS 卡片、连线、网格和步骤轨道表现流程、层级、因果链、二维矩阵或关系图，让知识结构本身可见。它不能只是一个标题加普通列表：应包含至少两个有明确教学作用的区域，例如带大数字的方法步骤、不同浅色的概念卡、当前步骤轨道、示范或 hint block。没有真实结构时应使用 `text`，不要把稀薄内容硬撑成满屏卡片。`richText` 只负责展示，不能接受输入或完成 Slice；老师确认教学设计和逐页计划后，Agent 才会调用内部的 `design-course-rich-text` specialist 生成安全的内联 HTML/CSS，不会借美化之名改写已确认的方法、案例、事实或题目。一个 Slice 应保持视觉可读，素材过多时拆页。课程结尾由学生数据与预先准备好的 fallback 总结共同支持，静态文本不得声称某个学生已经掌握内容。

开场、结尾与逐页 narration 的音频路径属于学生端 ship 阶段生成的 TTS 目标，不要求教师本地生成，也不会作为老师素材上传。当前本地预览使用 fallback 文本且静音。

## 媒体与交互检查

- 左右分屏强默认 `1:1`，两侧内容由共享 renderer 垂直居中。PDF 作为竖向页面在自己的栏位内居中显示，不因为是 PDF 就偏离 `1:1`；学生可以点击 PDF 标题栏的“放大阅读”，在接近全屏的弹窗中查看原文。只有“大视频 + 少量辅助文字”可以使用非对称比例，并把更宽一侧给视频。互动 HTML 保持声明的 `1:1` 或 `4:3` 比例并居中缩放，不得拉伸。
- 所有分栏槽位都必须非空。左右或上下分栏的每一侧都必须实际承载 Block；不允许把 2–3 个 Block 全堆在一侧，再用 `3:1` 留出空栏。一个聚焦内容使用 `full`；说明与作答并列时左右分配；连续堆叠的内容拆成多个 Slice。Agent 的结构检查和逐页截图自检都会发现这类问题。
- 需要作答的 Block 与参考或解释内容并排时，默认放在右侧。网格可以承载 2–4 个格子，是否使用由比较和分组关系决定，不机械按照元素数量套版。
- 两张横向图片只有在学生需要同时比较时才使用 `side-by-side`。超过两张图片，或多张竖图/长图并排会变得太小时，默认使用带“上一张 / 下一张”的 `gallery`；只有学习任务确实要求同时对照时才保留并排。
- 学生答题所需的参考材料尽量和题目放在同一个 Slice；不要要求学生为了作答频繁翻回上一页。内容无法在一屏内清晰呈现时，先调整教学顺序或拆分讲解，再进入作答。
- `full` 一页只承载一个聚焦 Block。文字和题目不能铺满超宽屏，也不能被压成横向薄条；素材过多时拆成多个 Slice。
- `pdf` Block 必须保留来源明确的原始 PDF 字节，并检查扩展名、文件头、EOF、路径安全与真实 renderer 行为。
- 视频必须是 MP4、H.264、`yuv420p`、faststart；存在音轨时使用 AAC。视频题只采用老师已经提供的问题；没有老师输入就不编造、不建议新增，也不生成视频交互。已有交互文件会检查时间范围、自动暂停、必做题和完成规则。
- AI 新写的单选题必须分散正确答案位置，不能把所有正确答案都默认放在 A；老师原有题目不因这条规则被静默改写。
- 开放表达或反思型填空必须采用“提交即可继续”，不能用关键词或正则表达式判断概念理解并把学生无限卡住。确实存在有限标准答案的短答题可以评分，但必须提供可操作的错误反馈，并在最多三次尝试后进入讲解或继续路径。单选题已有明确选项与反馈，不属于这一限制。
- HTML 在 iframe 中遵守 renderer 支持的消息协议。完成时必须提交规定的学生学习数据；自动播放音乐仍受浏览器 autoplay 策略约束，并需要在真实预览中验证。
- 旧 HTML 若使用 `INTERACTION_COMPLETE`、缺少握手或 `sessionToken`、在握手前静默丢弃消息，Agent 会备份原件并直接修复课程交付副本，不要求老师理解或修改协议代码；题目、答案、评分、完成门槛、DOM 和 CSS 必须保持不变。
- WEBVTT、JSON、HTML、图片、PDF 与视频均按课程内相对路径管理。

不兼容或过大的视频不得覆盖原文件。Agent 会先用 `ffprobe` 说明格式、时长和大小，给出输入、候选输出与处理取舍，得到老师确认后才用 `ffmpeg -n` 生成候选视频。原视频保持不变并作为回滚备份，每次处理的来源哈希和检查结果都作为独立历史记录保存在 `.course-work/video-backups/`。老师需要实际播放候选视频并再次确认；采用决定会绑定候选文件哈希，在此之前 Agent 不会修改 Blueprint 或课程素材引用。确认采用后，最终课程素材也不得覆盖已有的不同文件；Agent 会根据画面中的语义锚点逐个重新核对互动时间，记录旧时间、锚点和新时间，不能按新旧时长比例机械换算，并重新完成校验与真实预览。

## 预览、批注与修改

`preview-platform-course` 只绑定 `127.0.0.1`，这个本地预览链接只能在当前电脑查看。完成本地预览时，Agent 会主动提醒老师：需要同事或其他老师预览时，应在明确批准后发布到学生端，并分享学生端页面；不要发送课程工程让对方重新上传，也不要发送 ZIP 包或本地链接。页面使用真实学生端 renderer、内存 session adapter 和本地素材解析。批注 UI 位于 renderer 外部，并绑定 Course、Part、Slice、Block、图片 item 或 workflow Step 的稳定 ID；不会把 CSS selector、坐标或 DOM 结构当作修改目标。

批注模式可以打开或关闭。关闭时页面保持正常学生交互；打开时直接点击组件即可选定批注目标，且不会误触该组件。批注可以修改、删除、标记已完成或重新打开。

AI 交付预览前会先在检查模式访问每个 Slice 并逐页看截图。交给教师的默认预览同样使用检查模式，顶部有独立翻页控制，不必先完成题目；普通学生 Workflow 预览只在教师明确要求时另开。批注可以继续保留、修改、删除、标记完成或重新打开；老师标记解决的内容不会被新检查自动重开。修改后必须重新生成并预览当前版本。课程最后没有待处理批注时，页面会直接建议进入“发布到学生端”，但仍需要教师确认发布计划才会产生外部修改。

## 发布与安全边界

发布只由 `publish-platform-course` 执行，并要求老师对当前发布明确批准。新课程按四阶段流程完成检查；旧课程保留已有审查和发布状态，不因缺少后来新增的页面计划或视觉检查记录而返工。

- 33 门课程分别使用代码固定的 `course-01` 至 `course-33`；老师不能自定义 slug。同一课程永远使用同一个固定 slug，远端已存在时只能更新，不会再次创建。
- 素材使用 `courses/<slug>/<relativePath>` 的确定路径。
- 本地复用证明必须同时匹配 slug、相对路径和 SHA-256，避免重复上传；固定封面从不进入教师上传清单。同一工程反复保存不会重传未变化素材。若 `.course-work` 被删除、复制或丢失，由于服务端当前没有素材 checksum/existence 查询，工具会保守地把同一字节重新 PUT 到同一固定 key：会产生重复传输，但不会产生多个对象 key。
- 创建和更新都使用同一个 slug-keyed definition PUT；发布后再调用 ship 并读取课程状态和完整 definition 验证。
- published 课程的 definition PUT 会先改变线上字节，ship 会重新生成 TTS；dry run 会明确提示这两个风险。
- 接口为 last-writer-wins，当前没有 revision/optimistic concurrency。远端状态在批准后变化会阻止执行。

以上规则阻止今后为同一门目录课程创建新 slug。历史上已经使用任意 slug 创建出的重复课程不会被工具自动删除或合并，因为系统目前无法仅凭课程标题安全判定哪一条应保留；这类旧记录需要另做一次只读清点，再由管理员明确决定如何处理。

`OSS_ADMIN_KEY` 可以通过进程环境变量或被 Git 忽略的课程目录 `.env` 提供，且进程环境变量优先。工具不会把它写入参数、课程文件、`.course-work`、Git 或普通输出；Bearer 只发送给学生端管理 API，不会发送到预签名 OSS URL。构建、检查、预览或批注请求都不构成上传或发布授权。

## 本地目录

- `course/course.json`：确定性生成的学生端 CourseDefinition 2.0。
- `course/assets/`、`course/interactions/`：实际交付素材。
- `.course-work/`：Blueprint、决策、issues、校验、预览、批注、终审与发布恢复状态，不提交给学生端。
- `skills/`：教师主入口与内部专用 Skills。
- `course_toolkit/`、`scripts/`：共享 contract/renderer、确定性检查与命令行工具。

ZIP 不参与材料分析或发布。原始材料留在教师仓库内，工具只写课程目录、`.course-work` 与明确的生成文件。

## 管理员验证

```bash
python3 -m unittest discover -s tests -v
python3 scripts/validate-course-v2.py COURSE_ROOT --json
python3 scripts/review-course-v2.py COURSE_ROOT --json
```

33 张封面的一次性 OSS 预置先运行只读计划；它校验源 WebP、哈希、大小和 33 个固定 object key，不会上传：

```bash
python3 maintenance/seed-course-catalog-covers.py
```

只有管理员对这份完整计划明确批准后，才可在仓库根目录被 Git 忽略的 `.env` 中提供 `OSS_ADMIN_KEY` 并执行 `--execute`。该维护脚本不会安装到老师的 `_course-toolkit`，教师保存或发布课程也不会调用它。重复执行只会覆盖相同的 33 个固定 key，不会创建新的 object key，但仍会产生重复传输，因此不应把它当作日常发布步骤。

真实预览：

```bash
python3 scripts/preview-course.py COURSE_ROOT
```

该命令默认进入教师检查模式并显示顶部独立翻页。只有明确要体验学生端完成门槛时才追加 `--student-workflow`。

发布状态、preflight 和 execute 的详细命令见 `skills/publish-platform-course/SKILL.md`。真实发布会改变生产环境，不能用普通测试请求代替教师批准。
